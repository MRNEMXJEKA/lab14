# Практична робота №14

## Node.js: клієнт-серверна взаємодія, найпростіший сервер

### Формат

Комп'ютерний практикум

### Мета роботи

Встановити Node.js і написати найпростіший локальний сервер для застосунку: сервер роздає статичні файли застосунку (index.html, CSS, JS) і віддає JSON-дані домену через власний ендпоінт замість зовнішнього публічного API з практикуму 9. Клієнтський `fetch` перемкнуто на локальний URL за тим самим патерном `async/await` + `response.ok` + `try/catch`, що й у практикумі 9.

### Варіант завдання

**Варіант 7 — Список бажань (Wishlist)**

| Ендпоінт | Відповідь |
|---|---|
| `GET /api/wishes` | локальний список бажаних товарів |
| `GET /api/wishes/:id` | один товар або `404` |

### Хід роботи

**Крок 1. Встановлення Node.js LTS**
Встановлено Node.js LTS з nodejs.org. Версії перевірено командами `node -v` і `npm -v`.

**Крок 2. Ініціалізація серверного проєкту**
Створено теку `server/` і виконано `npm init -y`. У `package.json` додано скрипт `"start": "node server.js"`.

**Крок 3. Вибір підходу**
Обрано **Express** (`npm install express`): він сам розбирає параметри шляху (`:id`), ставить `Content-Type: application/json` для `res.json()` і роздає статичні файли, тож код коротший, ніж на чистому модулі `http`.

**Крок 4. Локальні дані**
У файлі `server/data/wishes.json` - 8 бажаних товарів у знайомій з практикумів 6, 9, 11 формі: `id`, `title`, `price`, `url`, `purchased`, `priority`, `saved`, `image`. Перші три збігаються з початковими бажаннями застосунку.

**Крок 5. Ендпоінт списку**
`GET /api/wishes` повертає весь масив через `res.json(wishes)` - зі статусом `200` і заголовком `Content-Type: application/json; charset=utf-8`.

**Крок 6. Ендпоінт деталей**
`GET /api/wishes/:id` шукає товар за `req.params.id` і повертає його, а якщо товару немає - статус `404` з JSON `{ "error": "Бажання з id … не знайдено" }`. Будь-який інший шлях `/api/...` також повертає `404` з JSON.

**Крок 7. Роздача статичних файлів**
Той самий сервер роздає клієнтську частину з попередніх практикумів: `index.html`, `script.js` і теку `css/`. Роздаються лише файли застосунку, а не вся тека проєкту, тож `server/`, `node_modules/`, `.git/` і звіт назовні не потрапляють. Сторінка й API працюють на одному порту (один origin), тому CORS не потрібен.

**Крок 8. Запуск сервера**
У теці `server/` виконано `npm start` - у терміналі з'являється `Сервер запущено на http://localhost:3000`. Застосунок відкривається за адресою `http://localhost:3000`, а відповідь ендпоінтів перевірено напряму в адресному рядку: `/api/wishes` і `/api/wishes/2`.

**Крок 9. Перемикання клієнтського fetch**
У `script.js` адресу зовнішнього JSONPlaceholder замінено на локальну: `const API_URL = "/api/wishes"`. Код запиту з практикуму 9 - `async/await`, перевірка `response.ok`, `try/catch/finally`, стан завантаження й повідомлення про помилку - залишився тим самим. Оскільки сервер віддає бажання вже у форматі застосунку, перетворення `todo → wish` спрощено. Кнопка «Завантажити з сервера» додає лише ті бажання, яких ще немає в списку, і зберігає їх в IndexedDB (практикум 11). На вкладці Network видно, що запит іде на `localhost:3000/api/wishes`.

**Крок 10. Перевірка обробки помилок**
- `GET /api/wishes/999` → `404` і `{ "error": "Бажання з id 999 не знайдено" }`;
- `GET /api/abc` → `404` і `{ "error": "Ендпоінт не знайдено" }`;
- якщо сервер зупинено, кнопка «Завантажити з сервера» показує «Список бажань недоступний офлайн», а картки лишаються на сторінці.

**Крок 11. Коментарі та збереження**
У `.gitignore` додано `node_modules/`. Над ендпоінтами й роздачею статики в `server.js` і над `API_URL` у `script.js` додано коментарі, зміни зафіксовано в Git.

```
git add .
git commit -m "Практична робота №14: Express-сервер, GET /api/wishes і /api/wishes/:id з 404, роздача статики, fetch на локальний API"
git push
```

### Запуск

```
cd server
npm install
npm start
```

Після цього відкрийте `http://localhost:3000`. Сторінку треба відкривати саме через Node-сервер, а не через Live Server: інакше запит `/api/wishes` піде на Live Server, який такого ендпоінта не має.

### Ендпоінти

| Метод і шлях | Статус | Тіло відповіді |
|---|---|---|
| `GET /api/wishes` | 200 | масив з 8 бажань |
| `GET /api/wishes/2` | 200 | `{ "id": 2, "title": "Навушники", ... }` |
| `GET /api/wishes/999` | 404 | `{ "error": "Бажання з id 999 не знайдено" }` |
| `GET /api/abc` | 404 | `{ "error": "Ендпоінт не знайдено" }` |
| `GET /`, `/script.js`, `/css/...` | 200 | файли клієнтської частини |

### Висновок

У результаті виконання практичної роботи для застосунку «Список бажань» написано найпростіший локальний сервер на Node.js з Express. Сервер віддає JSON-дані домену через власні ендпоінти: `GET /api/wishes` повертає весь список бажаних товарів, а `GET /api/wishes/:id` - один товар або код 404 з JSON-повідомленням. Той самий сервер роздає статичні файли клієнтської частини, тож сторінка й API працюють з одного origin без налаштування CORS. Клієнтський `fetch` перемкнуто із зовнішнього API на локальну адресу `/api/wishes`, а обробка `response.ok`, помилок і стану завантаження з практикуму 9 залишилася без змін. Коректні статус-коди та повідомлення про помилки перевірено в адресному рядку браузера й на вкладці Network.
